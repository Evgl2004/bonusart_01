# F11. Связь `DispatchTask` с `MailingGuest` и тех-админка сопровождения

## Цель этапа
1. Добавить явную связь между задачами доставки и строками массовой рассылки:
   - `DispatchTask.mailing_guest -> MailingGuest`.
2. Расширить Django Admin как операционную панель для технического сопровождения очередей.

## Что изменено
1. В модель `DispatchTask` добавлено nullable-поле:
   - `mailing_guest = ForeignKey(MailingGuest, null=True, on_delete=SET_NULL)`.
2. В producer массовой рассылки при создании `DispatchTask` теперь записывается:
   - `mailing_guest=row`.
3. В `admin.py` добавлены/расширены технические разделы:
   - `BotProfileAdmin`;
   - `GuestBotBindingAdmin`;
   - `MailingAdmin`;
   - `MailingGuestAdmin`;
   - `DispatchTaskAdmin`.

## Практическая польза
1. В `DispatchTask` сразу видно, к какой строке рассылки относится задача.
2. Техспециалист может в админке:
   - фильтровать задачи по провайдеру, приоритету, статусу;
   - смотреть ошибки и прогресс попыток;
   - выполнять массовые действия (`requeue`, `defer`, `cancel`).
3. Для `GuestBotBinding` доступны быстрые действия включения/остановки отправки.

## Замечание по производительности
Поле `ForeignKey` добавляется как nullable и не изменяет критический путь обработки сообщений.
Связь используется для диагностики/аудита и не мешает масштабированию очереди.
