# F17. Roadmap развития пользовательского дашборда (v1.1+)

## Статус документа
Рабочий план следующей итерации после внедрения `v1` дашборда на Django + Apache ECharts.

## Что уже сделано (база)
1. Реализована страница `/analytics/` с фильтрами по периоду и заведению.
2. Реализованы `6 KPI` и `3 графика`.
3. Добавлен сервис агрегации данных дашборда.
4. Добавлены автотесты на сервис и представление.

Связанный коммит:
1. `0952bf3` — `feat(analytics): дашборд v1 на Django + ECharts`.

## Подтверждённый план v1.1-v1.6

### v1.1. Drill-down по заведению
Цель:
1. Дать возможность из общего дашборда перейти в карточку конкретного заведения.
2. Показать внутри карточки заведения:
   1. топ гостей;
   2. топ фокусных категорий;
   3. динамику выручки/заказов по дням;
   4. долю «спящих гостей».

Результат:
1. Технический специалист и маркетолог видят детализацию без ручных SQL-запросов.

Статус:
1. `planned`.

### v1.2. Производительность и устойчивость
Цель:
1. Снизить нагрузку на БД при частом открытии аналитики.
2. Ускорить первый и повторный рендер страницы.

Задачи:
1. Кэшировать тяжёлые срезы на короткий TTL.
2. Проверить индексы под фильтры `period_days` и `department_id`.
3. Добавить диагностику времени построения payload.

Статус:
1. `planned`.

### v1.3. Расширение бизнес-метрик
Цель:
1. Добавить положительные и риск-метрики в одном экране.

Задачи:
1. Метрики активности:
   1. активные;
   2. спящие;
   3. «пропавшие» гости.
2. Балансовые метрики:
   1. накоплено бонусов;
   2. списано бонусов;
   3. соотношение накопления/списания.

Статус:
1. `planned`.

### v1.4. Привязка к сценариям уведомлений
Цель:
1. Использовать аналитику для запуска авто-рассылок напрямую из сегментов.

Задачи:
1. Связать видимые сегменты с `NotificationScenario`.
2. Добавить безопасный запуск «сегмент -> NotificationEvent -> DispatchTask».
3. Протоколировать запуск и итог доставки по сегменту.

Статус:
1. `planned`.

### v1.5. Наблюдаемость и контроль качества данных
Цель:
1. Быстро находить «разрывы» в потоке данных webhook/OLAP/агрегатов.

Задачи:
1. Добавить технический блок качества:
   1. дата последней синхронизации;
   2. количество ошибок в журналах;
   3. количество «пустых» срезов.
2. Добавить alert-правила на аномалии.

Статус:
1. `planned`.

### v1.6. Приёмка перед production
Цель:
1. Подтвердить готовность к выкладке на боевой контур.

Задачи:
1. Smoke-проход на копии БД.
2. Проверка миграций и отката.
3. Проверка пользовательских сценариев:
   1. фильтры;
   2. рендер графиков;
   3. корректность KPI.

Статус:
1. `planned`.

## Definition of Ready для старта v1.1
1. Утверждён набор экранов drill-down.
2. Утверждён список метрик на карточке заведения.
3. Утверждён порядок доступа (кто видит общую аналитику и детализацию).
