# F16. План внедрения OLAP-аналитики по чекам (поэтапно, без поломки прод-контура)

## Статус документа
Черновик для согласования и фиксации рабочей последовательности.
Опирается на архитектурный blueprint F15.

## Цель F16
Реализовать слой аналитики чеков и категорий номенклатуры на основе OLAP:
1. с минимальным риском для действующего webhook-контура;
2. с поэтапными логическими коммитами;
3. с обязательной миграционной дисциплиной Django;
4. с русскоязычной документацией и логированием.

## Базовые правила выполнения
1. Все изменения схемы только через Django migrations.
2. Каждый этап завершать зелёными проверками (`check`, `makemigrations --check`, целевые тесты).
3. Не удалять текущий рабочий контур рассылки; новый слой подключать постепенно.
4. Использовать только русские термины в документации и логах.

## Этапы внедрения (S1-S13)

### S1. Техническая проверка OLAP-фильтров по идентификаторам
Задачи:
1. Подтвердить рабочую фильтрацию по:
   1. `Department.Id`;
   2. `Department.Code`;
   3. `RestaurantSection.Id` (как резерв).
2. Зафиксировать итоговое правило отбора заведений в проектной документации.
3. Подготовить эталонные примеры запросов и ответов для тестов.

Результат:
1. Документ с подтверждённым рабочим способом фильтрации.
2. Тестовые примеры для регрессии интеграции.

Коммит:
1. `docs(olap): зафиксировать рабочие фильтры и эталонные запросы`

Статус:
1. `completed` — результаты зафиксированы в `docs/architecture/F16_S1_olap_filter_validation.md`.

### S2. Миграции: журнал синхронизации чеков и сырые строки OLAP
Задачи:
1. Добавить таблицы:
   1. `olap_check_sync_journal`;
   2. `olap_sales_raw_line`.
2. Добавить индексы и ограничения идемпотентности.
3. Добавить статусную модель обработки (`new|in_progress|loaded|retry|failed|skipped`).

Результат:
1. Схема БД для безопасной дозагрузки данных из OLAP.

Коммит:
1. `feat(olap): журнал синхронизации чеков и сырые строки OLAP`

### S3. Миграции: справочник категорий и таблица интересующих категорий
Задачи:
1. Добавить:
   1. `olap_dish_category_dict`;
   2. `olap_focus_category`.
2. Добавить админские ограничения целостности и уникальности.

Результат:
1. Явный управляемый бизнес-слой «какие категории считаем приоритетными».

Коммит:
1. `feat(olap): справочник категорий и приоритетные категории`

### S4. Клиент OLAP и сервисы загрузки порциями
Задачи:
1. Реализовать сервис авторизации в iiko (`/resto/api/auth`) с кэшем ключа.
2. Реализовать сервис запросов в OLAP (`/resto/api/v2/reports/olap`).
3. Реализовать загрузку порциями с повторными попытками и журналированием ошибок.

Результат:
1. Стабильный сервис интеграции с OLAP.

Коммит:
1. `feat(olap): клиент и сервис загрузки данных порциями`

### S5. Воркер дозагрузки чеков из журнала синхронизации
Задачи:
1. Добавить management-команду воркера дозагрузки.
2. Реализовать цикл:
   1. взять новые записи журнала;
   2. сгруппировать в порции;
   3. запросить OLAP;
   4. сохранить `olap_sales_raw_line`;
   5. обновить статусы журнала.
3. Реализовать graceful shutdown и безопасное завершение.

Результат:
1. Автономный контур дозагрузки чеков без блокировки webhook.

Коммит:
1. `feat(olap): воркер дозагрузки чеков и управление статусами`

### S6. Построение факта чека (`order_fact`)
Задачи:
1. Добавить таблицу `order_fact`.
2. Реализовать преобразование из сырых строк:
   1. одна запись = один чек;
   2. корректные суммы до/после скидок;
   3. признаки купона и типа заказа.
3. Обеспечить идемпотентное обновление при повторной загрузке.

Результат:
1. Быстрый и устойчивый слой для среднего чека и частоты.

Коммит:
1. `feat(analytics): построение факта чека из сырых строк OLAP`

### S7. Дневной слой по категориям
Задачи:
1. Добавить таблицу `guest_restaurant_daily_category_fact`.
2. Реализовать ежедневный (и инкрементальный) пересчёт из `order_fact` + сырых строк.
3. Добавить контроль качества пересчёта и журнал метрик.

Результат:
1. Базовый слой для расчёта окон `7/14/30/60/180`.

Коммит:
1. `feat(analytics): дневные итоги категорий по гостям и заведениям`

### S8. Оконные метрики и рейтинг гостя

3. Реализовать вычисление `rating_score` по согласованной формуле.

Результат:

Коммит:

### S9. Интеграция с авто-сценариями уведомлений

## Проверки на каждом этапе
1. `python manage.py check`
2. `python manage.py makemigrations --check`
3. целевые тесты изменённого модуля
4. smoke-команда после деплоя (без отправки сообщений пользователям)

## Definition of Done для F16
1. Синхронизация чеков из OLAP работает штатно и устойчиво к повторам.
2. Сырые данные и агрегаты согласованы и проверены на контрольной выборке.
3. Периоды `7/14/30/60/180` считаются из дневного слоя без тяжёлых онлайн-расчётов.
4. Таблица «интересующих категорий» участвует в сегментации и отчётах.
5. Сценарии рассылок используют новый аналитический слой без поломки текущей очереди доставки.
