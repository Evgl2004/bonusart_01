# F8. Унифицированный producer уведомлений для бизнес-событий

## Цель этапа
Убрать жёсткую зависимость отправки от формата веб-хука и дать общий API:
1. Любая бизнес-логика может поставить задачу уведомления в universal queue.
2. Веб-хук становится только одним из источников (`source_type=webhook`).
3. Повторное использование логики маршрутизации и дедупликации.

## Что добавлено
1. Новый модуль:
   - `guests/services/universal_queue/notification_producer.py`
2. Общий метод:
   - `enqueue_guest_notification_tasks(...)`

## Что изменено
1. `webhook_producer` переведён на вызов общего producer-а:
   - теперь он только:
     - парсит webhook,
     - определяет гостя/приоритет/текст,
     - передаёт данные в общий слой постановки задач.

## Логика общего producer-а
1. Принимает гостя, текст, приоритет, `source_type`, `source_key`, payload.
2. Находит каналы в порядке:
   - `GuestBotBinding` (новая модель),
   - fallback `GuestChannelLink` (legacy Telegram, если включён).
3. Создаёт `DispatchTask` по каждому каналу:
   - сохраняет `legacy_channel_id` в payload для fallback-токена;
   - использует `idempotency_key`, если передан `source_key`.

## Практический эффект
1. Легко подключать новые источники событий (например, баланс/статусы заказа) без копирования кода.
2. Повышается консистентность маршрутизации (`primary_only`, fallback, дедупликация).
3. Упрощается сопровождение и расширение источников уведомлений.
