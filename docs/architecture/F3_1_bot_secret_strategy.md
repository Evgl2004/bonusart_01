# F3.1: Стратегия хранения токенов ботов

## Задача

Снизить риск хранения API-токенов в базе данных в открытом виде.

## Решение

В `BotProfile` добавлено поле `secret_ref`.

Логика получения токена:

1. Если задан `secret_ref`, токен читается из переменной окружения с этим именем.
2. Если `secret_ref` не задан, используется legacy-поле `token`.

Таким образом, текущая система остаётся совместимой, но новые настройки
можно переводить на безопасный режим без хранения секрета в БД.

## Пример

В таблице `bot_profiles`:

1. `code = tg_main`
2. `secret_ref = BOT_TOKEN_TG_MAIN`

В `.env`:

```env
BOT_TOKEN_TG_MAIN=123456:ABCDEF...
```

## Дальнейший шаг

На этапе интеграции провайдерных воркеров отправка будет использовать
метод `BotProfile.resolve_token()`, чтобы единообразно брать токен
из окружения или legacy-поля.
