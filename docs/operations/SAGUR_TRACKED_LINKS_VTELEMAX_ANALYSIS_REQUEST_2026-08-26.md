# Запрос SAGUR команде vtelemax по новому набору со ссылочной кнопкой

Дата: 2026-08-26.

## Контекст

SAGUR проектирует новый набор кнопок `rating_menu_link` — «Оценка + ссылка + главное меню».

Утверждённая клавиатура содержит три ряда:

1. `l` — «Нравится» и `d` — «Не нравится»;
2. одна обычная URL-кнопка без служебного JSON и без обратного действия;
3. `m` — «Меню».

Ссылочная кнопка получает уникальный адрес вида:

```text
https://sagur.24vds.ru/r/v1/<32-символьный-токен>
```

Кнопки `l`, `d`, `m` продолжают использовать действующий служебный JSON версии 2 и составные действия `ldm`, `dlm`, `mld`. Новое действие для ссылки в пакет vtelemax → SAGUR не добавляется. Переход по ссылке учитывает непосредственно SAGUR.

Планируемые типы платформенных кнопок:

- Telegram — URL-кнопка с `text`, `url` и поддерживаемым основным стилем;
- VK — кнопка `open_link` с `label` и `link`;
- MAX — кнопка `type=link` с `text` и `url`.

## Требуемый анализ vtelemax

Просим проверить фактический код адаптеров Telegram, VK и MAX и дать отдельный ответ по каждой платформе.

При обработке оценки `l` или `d` vtelemax должен:

1. получить фактическую клавиатуру исходного сообщения;
2. удалить только кнопки `l` и `d` этой интерактивности;
3. сохранить ссылочную кнопку без изменения типа, подписи и URL;
4. сохранить ссылочную кнопку во втором ряду;
5. сохранить кнопку `m` в третьем ряду до редактирования и в следующем ряду после удаления пустого ряда оценок;
6. сохранить текст сообщения, стили поддерживаемых кнопок и остальные вложения;
7. обеспечить дальнейшую многократную работу `m`;
8. не формировать событие SAGUR при обычном открытии URL-кнопки.

Ожидаемый результат клавиатуры после принятой оценки:

```text
ссылочная кнопка
Меню
```

## Просьба в ответе

Для Telegram, VK и MAX просим указать:

- какие функции и адаптеры были проверены;
- как из фактического сообщения извлекаются callback-кнопки и URL-кнопки;
- сохраняются ли URL-кнопка, её ряд, подпись и адрес при текущем редактировании;
- не пытается ли код разобрать URL-кнопку как служебный JSON SAGUR;
- требуется ли изменение производственного кода vtelemax;
- какие положительные и отрицательные автоматические тесты необходимо добавить;
- какие ограничения платформы требуют живой сквозной проверки.

Если изменение кода не требуется, просим подтвердить это не общим ответом, а отдельным обоснованием для каждого из трёх адаптеров. Если изменение требуется хотя бы для одной платформы, просим указать точную причину и границу доработки.

До получения этого ответа SAGUR считает совместимость текущего кода vtelemax предварительной, а не окончательно подтверждённой.
