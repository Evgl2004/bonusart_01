# План завершения купонного контура SAGUR + iikoCard + vtelemax

Дата фиксации: 2026-05-15.

Документ фиксирует последовательный план доработок после аудита текущего состояния проекта. Реализация идет итерациями: перед каждой итерацией формулируется цель, открытые вопросы задаются текстом в чате, после выполнения запускаются релевантные тесты через `scripts/run_pytest.ps1`.

## 3. Перевести внешний транспорт vtelemax на batch-формат

Цель: отправлять купонные события во vtelemax транспортными пачками, не меняя поштучный учет назначений внутри SAGUR.

Принятое решение:

- внутри SAGUR одно назначение купона остается отдельной учетной записью `CouponCampaignAssignment`;
- в очереди `CouponVtelemaxSyncQueue` одно событие остается отдельной учетной единицей с собственным `event_id`;
- наружу во vtelemax события отправляются пачками по `direction` через payload с `request_id`, `sent_at`, `direction`, `items[]`;
- каждый item содержит собственный `event_id`;
- подтверждение/ошибка обрабатывается по каждому `event_id` отдельно;
- `canceled -> release` выполняется только после подтверждения конкретного item.

Состав работ:

- изменить delivery-сервис `VtelemaxCouponSyncService`;
- добавить item-level обработку `acked/error/rejected`;
- сохранить retry и HMAC-подпись;
- обновить контрактные тесты;
- подготовить текст для vtelemax по целевому batch-контракту.

Критерий готовности:

- один HTTP POST может содержать до `VTELEMAX_COUPON_SYNC_BATCH_SIZE` items одного `direction`;
- частичное подтверждение не ломает всю пачку;
- rejected/error item остается в retry/error-состоянии с понятной причиной;
- release купона при `canceled` выполняется только для ACKed item.

Проверка:

- `powershell -ExecutionPolicy Bypass -File scripts/run_pytest.ps1 guests/tests/test_vtelemax_coupon_sync_service.py guests/tests/test_coupon_campaign_lifecycle_service.py guests/tests/test_coupon_campaign_gate_service.py`

Цель: закрыть требование Stage A/B/Roadmap по CSV `deleted=1` для iikoCard либо явно вынести его за релиз.

Вопрос перед этапом:

Состав работ при включении в релиз:

- отбирать купоны закрываемой кампании по согласованным статусам;

Критерий готовности:

- документация закрытия кампании соответствует коду.

Проверка:

## 5. Финальная релизная проверка и E2E SAGUR ↔ vtelemax

Цель: пройти релизный сценарий от генерации пула до `canceled -> release -> reassign`.

Состав работ:

- обновить релизный чек-лист;
- обновить E2E-чек-лист SAGUR ↔ vtelemax;
- выполнить купонный регрессионный прогон;
- отдельно зафиксировать нерелевантные падения полного `guests/tests`, если они останутся вне купонного контура.

Критерий готовности:

- купонный контур зеленый;
- E2E-чек-лист проходит на тестовом окружении;
- все отложенные риски явно помечены как backlog.

Проверка:

- купонный набор тестов;
- по возможности полный `guests/tests`;
- ручной E2E по чек-листу.
