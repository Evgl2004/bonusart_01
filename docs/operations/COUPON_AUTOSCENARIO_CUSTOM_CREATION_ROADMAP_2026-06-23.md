# Дорожная карта: создание купонных автосценариев из интерфейса

Дата: 2026-06-23.

## Цель

Дать маркетологу возможность создавать отдельные купонные автосценарии из пользовательского интерфейса: со своим названием, кодом, шаблоном сообщения, правилами купонов, отбором гостей и настройками доставки.

Первый рабочий пример: отдельный автосценарий для гостей «Сами Сусами», которые были в заведении хотя бы один раз и не возвращались 30+ дней.

## Почему нужна доработка

Сейчас в системе есть купонные автосценарии, но их коды заранее заложены в коде приложения. Один код одновременно означает две разные вещи:

- постоянную точку отчётности, по которой потом собирается история запусков и эффективность;
- способ расчёта аудитории: день рождения, заполненная дата рождения или отсутствие визитов.

Для пользовательских автосценариев эти роли нужно разделить:

- код автосценария остаётся постоянным именем конкретной маркетинговой акции;
- тип автосценария определяет, какую логику отбора гостей использовать.

Так мы сможем создать, например, отдельный автосценарий `susami_inactive_30d_kanpeti`, но считать его по типу «гость не был N дней + купон».

## Что важно не сломать

- Существующие автосценарии должны продолжить работать без изменения настроек.
- Отчёты должны оставаться привязанными к конкретному автосценарию, а не смешиваться между разными акциями.
- Пилотный режим, контрольные телефоны, выбор ботов, выбор заведений для купонов и очистка пилотных купонов должны работать как раньше.
- Сценарии без купонов не должны попасть в купонный плановый запуск.

## Шаг 1. Тип купонного автосценария

Добавить в купонную настройку автосценария отдельное поле «Тип купонного автосценария».

Первый набор типов:

- гость не был N дней + купон;
- день рождения + купон;
- дата рождения заполнена + купон.

Миграция должна заполнить тип для уже существующих автосценариев по их текущим кодам.

## Шаг 2. Расчёт и запуск по типу

Перевести расчёт аудитории и запуск с проверки конкретных кодов на проверку типа купонного автосценария.

После этого конкретный код автосценария сможет быть любым уникальным кодом, а логика расчёта будет определяться выбранным типом.

## Шаг 3. Создание через пользовательский интерфейс

Добавить на экран автосценариев кнопку «Создать купонный автосценарий».

Минимальный состав формы создания:

- название автосценария;
- код автосценария;
- тип купонного автосценария;
- шаблон сообщения;
- начальное состояние «Черновик».

После создания пользователь должен попадать на уже существующую страницу настройки, где заполняются лимиты, боты, окно отправки, правила купонов, отбор гостей по заведению и пилотная проверка.

## Шаг 4. Проверка и эксплуатация

Перед боевым запуском нового автосценария проверяем:

- миграции применены;
- системная проверка Django проходит без ошибок;
- расчёт автосценария строится по выбранному типу;
- пилотный запуск создаёт назначение, очередь vtelemax и сообщение;
- отчёт по автосценарию видит историю именно нового кода.

## Коммиты

Работу разбиваем на логические коммиты:

1. Зафиксировать дорожную карту.
2. Добавить тип купонного автосценария и миграцию.
3. Перевести расчёт и запуск на тип купонного автосценария.
4. Добавить создание купонного автосценария в пользовательском интерфейсе.
5. Добавить проверки и серверный скрипт готовности.
