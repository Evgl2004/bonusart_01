# Дорожная карта: отбор купонного автосценария по заведению

Дата: 2026-06-23.

## Цель

Добавить для купонных автосценариев безопасный отбор гостей по конкретному заведению: гость был в выбранном заведении хотя бы один раз и не был именно в этом заведении заданное количество дней.

Первый рабочий пример: гости, которые были в заведении «Сами Сусами» хотя бы один раз и не были в «Сами Сусами» 30+ дней.

## Что важно не сломать

- Текущий режим без ограничения по заведению должен работать как раньше: сценарий «гость не был 30 дней + купон» смотрит последнее посещение по всей сети.
- Настройка «как выбрать заведение для купона» остается отдельной логикой. Она отвечает за то, из какой строки правил взять серию купонов.
- Новый отбор гостей по заведению не должен менять правила выбора купона, если он явно не включен.
- Пилотный режим, контрольные телефоны, проверка расчета и ограничения по ботам должны продолжить работать без изменений.

## Шаг 1. Модель и миграция

Добавить в купонную настройку автосценария отдельные поля:

- режим отбора гостей по заведению;
- код заведения для отбора;
- название заведения для отображения.

По умолчанию новый режим выключен, поэтому существующие автосценарии не меняют поведение после миграции.

## Шаг 2. Расчет аудитории

Если новый режим выключен, используется текущий расчет.

Если новый режим включен, расчет должен:

- найти гостей, которые были в выбранном заведении хотя бы один раз;
- взять последнее посещение именно этого заведения;
- оставить только тех, у кого последнее посещение выбранного заведения было не позже порога, например 30+ дней назад;
- дальше применить существующие проверки: бот, согласие на сообщения, защита от повторной выдачи, пауза перед повтором, пилотные ограничения, наличие купона.

## Шаг 3. Форма настройки

На странице настройки купонного автосценария добавить отдельный блок «Отбор гостей по заведению».

Блок должен быть отделен от блока «Заведения и серии купонов», чтобы было понятно:

- первый блок отвечает за то, каких гостей брать;
- второй блок отвечает за то, какой купон выдать.

## Шаг 4. Проверка расчета

В проверке расчета и серверной команде нужно показывать, включен ли отбор по заведению и какое заведение выбрано.

Это нужно, чтобы перед запуском было видно, что сценарий действительно считает «не был 30+ дней в Сами Сусами», а не «не был 30+ дней по всей сети».

## Шаг 5. Тесты

Проверить отдельными тестами:

- без нового режима старый расчет не меняется;
- гость, который был в «Сами Сусами» 45 дней назад и был в другом заведении 5 дней назад, попадает в отбор;
- гость, который был в «Сами Сусами» 10 дней назад, не попадает в отбор;
- гость, который никогда не был в «Сами Сусами», не попадает в отбор;
- пилотный телефон продолжает работать поверх нового отбора.

## Коммиты

Работу разбиваем на логические коммиты:

1. Зафиксировать дорожную карту.
2. Добавить поля настройки и миграцию.
3. Добавить расчет аудитории по заведению.
4. Добавить настройки на форму и вывод в проверку.
5. Добавить тесты и проверочные команды.
