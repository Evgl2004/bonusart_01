# Политика жизненного цикла купонов SAGUR + iikoCard + vtelemax

Дата фиксации: 2026-05-15.

Документ фиксирует согласованную бизнес-логику статусов купонов после завершения купонной кампании.

## 1. Общие принципы

- SAGUR, vtelemax и отчёты должны использовать одинаковый технический и логический смысл статусов купона.
- iikoCard остаётся источником факта реального применения купона.
- Купоны не удаляются из iikoCard автоматически после завершения кампании.
- Автоматический возврат купона в пул разрешён только для безопасного сценария `reserved -> canceled -> подтверждение release`.

## 2. Основные статусы

| Статус | Русское название | Смысл |
|---|---|---|
| `reserved` | Зарезервирован | Купон закреплён за гостем, но рассылка ещё не ушла. |
| `sent` | Отправлен | Купон отправлен/дошёл до этапа фактической коммуникации. |
| `used` | Использован | Купон использован в период действия акции. |
| `used_after_campaign` | Использован после завершения акции | Купон использован в iikoCard после окончания окна кампании. |
| `expired` | Истёк | Кампания завершилась, купон не был использован в окно акции и скрывается в vtelemax. |
| `canceled` | Отменён | Купон отменён; release в пул возможен только для reserved и только после подтверждения vtelemax. |
| `error` | Ошибка | Назначение или синхронизация завершились ошибкой. |

## 3. Использование после завершения акции

Если купон был помечен как `expired`, но позже из iiko/OLAP пришёл факт применения, SAGUR переводит назначение и запись реестра в статус `used_after_campaign`.

Критерий позднего использования:

- в первую очередь используется бизнес-дата заказа из OLAP;
- если бизнес-дата позже даты окончания кампании, статус должен быть `used_after_campaign`;
- если бизнес-дата совпадает с датой окончания кампании, дополнительно учитывается фактическое время применения/первого обнаружения относительно `scheduled_time_end`;
- если бизнес-даты нет, используется фактическое время применения/первого обнаружения.

Такой купон:

- учитывается в общем количестве использованных купонов;
- отдельно учитывается в метрике поздних применений;
- не возвращается в пул доступных купонов;
- передаётся во vtelemax как `status_update` со статусом `used_after_campaign`;
- должен быть скрыт/помечен во vtelemax в том же смысле, что и в SAGUR.

## 4. Завершение кампании

После завершения окна кампании:

- `sent -> expired`;
- `reserved -> canceled` без автоматического release, если речь о post-campaign close;
- по изменениям ставятся `status_update` события во vtelemax;
- `release_to_pool=false`, если купон был отправлен, истёк, использован или отменён после завершения кампании.

## 5. Отмена кампании до отправки

Для неотправленных купонов допустим безопасный release:

1. SAGUR переводит `reserved -> canceled`.
2. SAGUR отправляет во vtelemax `status_update:canceled` с `meta.release_to_pool=true`.
3. vtelemax скрывает купон у гостя и возвращает подтверждение по конкретному `event_id`.
4. Только после подтверждения SAGUR возвращает купон в `verified_loaded`.

## 6. iikoCard `deleted=1`

CSV-закрытие/удаление купонов в iikoCard через `deleted=1` в текущий релиз не включается.

Причина: это бизнес-решение маркетинга. Купон может быть использован гостем позже формального окончания акции, и такой факт нужен для аналитики поздней конверсии.

Возможный будущий этап:

- ручной экспорт CSV `deleted=1`;
- отдельный runbook;
- явное решение бизнеса, какие купоны закрывать в iikoCard и когда.
