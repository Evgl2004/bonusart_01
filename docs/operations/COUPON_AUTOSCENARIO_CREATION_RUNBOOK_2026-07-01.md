# Создание и запуск купонного автосценария

Документ описывает рабочий путь создания обособленного купонного автосценария без ручного редактирования Django Admin.

## 1. Что создаётся

Купонный автосценарий состоит из связанных сущностей:

- `NotificationScenario` — сценарий уведомлений, шаблон сообщения, разрешённые боты, режим отправки.
- `CouponAutomationConfig` — купонная настройка: состояние, лимиты, срок купона, правила отбора и выдачи.
- `CouponAutomationRule` — правила выбора купонной серии по заведению или всей сети.
- `MessageTemplate` — текст сообщения гостю с обязательным параметром `{coupon_code}`.
- Очереди vtelemax, iikoCard и универсальной доставки — рабочий контур после запуска.

Новый пользовательский автосценарий создаётся выключенным и в состоянии `Черновик`. Это защищает от случайной выдачи купонов.

## 2. Основной путь через интерфейс

1. Открыть `Рассылки -> Автосценарии`.
2. Нажать `Создать автосценарий` или `Создать на основе типового`.
3. Выбрать типовую основу:
   - `Гость не был N дней + купон`;
   - `День рождения + купон`;
   - `Дата рождения заполнена + купон`.
4. Указать новый код, название, шаблон сообщения и разрешённые боты.
5. После создания открыть вкладки настроек:
   - `Состояние` — состояние, лимит прохода, срок купона, пауза перед повтором.
   - `Сообщения` — шаблон, режим отправки, окно отправки, боты.
   - `Цепочка` — для двухсоставных сценариев.
   - `Купоны` — серии и правила по заведениям.
   - `Пилот` — контрольные телефоны.
   - `Дополнительно` — условия iikoCard и карточка купона.
6. Открыть `Пульт`.
7. Нажать `Проверить готовность`.

Если есть блокировки, пульт покажет конкретный раздел настроек, который нужно исправить.

## 3. Сервисный путь через команду

Команда `create_coupon_autoscenario` использует ту же валидацию, что и пользовательский мастер. Без `--confirm` она выполняет сухой прогон: проверяет данные и ничего не пишет в базу.

Пример сухого прогона с новым шаблоном:

```bash
python manage.py create_coupon_autoscenario \
  --code sami_susami_kanpeti_30d \
  --name "Сами Сусами: не был 30 дней + Канпети" \
  --scenario-type inactive_days_coupon \
  --inactive-days 30 \
  --template-name "Канпети для остывших гостей" \
  --template-text "Гамарджоба! Ваш купон: {coupon_code}" \
  --bot-profile-code tg_main
```

Создание после проверки:

```bash
python manage.py create_coupon_autoscenario \
  --code sami_susami_kanpeti_30d \
  --name "Сами Сусами: не был 30 дней + Канпети" \
  --scenario-type inactive_days_coupon \
  --inactive-days 30 \
  --template-name "Канпети для остывших гостей" \
  --template-text "Гамарджоба! Ваш купон: {coupon_code}" \
  --bot-profile-code tg_main \
  --confirm
```

Создание на основе существующего автосценария:

```bash
python manage.py create_coupon_autoscenario \
  --code sami_susami_kanpeti_30d_copy \
  --name "Сами Сусами: копия купонного автосценария" \
  --source-config-id 123 \
  --confirm
```

Команда копирует безопасные параметры и правила из указанной купонной настройки, но новый автосценарий всё равно создаётся в состоянии `Черновик`.

## 4. Диагностика перед пилотом

Проверить связность и ближайший план:

```bash
python manage.py plan_coupon_autoscenario \
  --scenario-code sami_susami_kanpeti_30d \
  --scan-limit 1000
```

Команда показывает:

- включён ли сценарий уведомлений;
- какой шаблон привязан;
- какие активные боты разрешены;
- включено ли расписание купонных автосценариев;
- входит ли код сценария в список планового запуска;
- состояние купонной настройки;
- блокировки аудитории, каналов, купонов и повторной выдачи;
- плановые пары гость/купон.

## 5. Пилот

1. В настройках перевести автосценарий в состояние `Пилот`.
2. Указать контрольные телефоны.
3. Проверить, что шаблон содержит `{coupon_code}`.
4. В пульте нажать `Проверить готовность`.
5. Нажать `Пилотная волна`.

Командный вариант пилота:

```bash
python manage.py execute_coupon_autoscenario_pilot \
  --scenario-code sami_susami_kanpeti_30d \
  --scan-limit 1000
```

Фактическое резервирование купона и создание событий vtelemax выполняется только с подтверждением:

```bash
python manage.py execute_coupon_autoscenario_pilot \
  --scenario-code sami_susami_kanpeti_30d \
  --scan-limit 1000 \
  --confirm
```

После пилота нужно дождаться подтверждения vtelemax, доставки сообщения и проверить купон в боте.

## 6. Контролируемый боевой запуск

1. В настройках перевести автосценарий в состояние `Активен`.
2. Для состояния `Активен` выбрать режим отправки `Равномерно в окне`.
3. Убедиться, что лимит прохода утверждён.
4. В пульте нажать `Проверить готовность`.
5. Нажать `Создать малый запуск`.
6. Проверить:
   - создан `CouponAutoscenarioRun`;
   - назначены реальные гости;
   - создана очередь vtelemax;
   - после подтверждения vtelemax появились задачи доставки;
   - результат отображается в отчёте `Отчёты -> Автосценарии`.

## 7. Плановый запуск

Плановый запуск работает только при одновременном выполнении условий:

- `NotificationScenario.is_active=True`;
- `CouponAutomationConfig.execution_mode=Активен`;
- код сценария указан в `COUPON_AUTOSCENARIO_SCHEDULE_CODES`;
- включён `COUPON_AUTOSCENARIO_SCHEDULE_ENABLED`;
- расписание Django Q синхронизировано.

Локальная проверка переменных описана в `.env.sample`.

На боевом сервере перед командами сначала проверить фактический путь, контейнеры и compose:

```bash
pwd
ls -la
sudo docker compose ps
```

После проверки окружения команда в контейнере приложения обычно выглядит так:

```bash
sudo docker compose exec app-bonus python manage.py plan_coupon_autoscenario \
  --scenario-code sami_susami_kanpeti_30d \
  --scan-limit 1000
```

## 8. Что не делать

- Не создавать рабочий автосценарий прямым редактированием `NotificationScenario` и `CouponAutomationConfig` в Django Admin.
- Не переводить сценарий в `Активен`, пока не настроены шаблон, боты, купонные правила и пилот.
- Не использовать шаблон без `{coupon_code}`.
- Не включать режим `Сразу` для боевого состояния `Активен`.
- Не смешивать эту механику с будущей задачей изображений и игровых автосценариев.
