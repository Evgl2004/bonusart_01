# Дорожная карта: рассылка исторической Telegram-аудитории

Дата фиксации: 2026-07-04.

## Цель

Вернуть гостей, которые есть в общей базе гостей и аналитике посещений, получили разовую Telegram-рассылку кампании #10, но пока не работают с нами через новый контур бота.

## Ключевое решение

Мы не создаём отдельный контур гостей и отдельный контур OLAP-аналитики. Фактическая база гостей и витрины посещений уже существуют в основном контуре. Новая сущность хранит только проверенный исторический Telegram-адрес доставки и его состояние.

Название сущности: **исторический Telegram-канал**.

## Что хранит новая сущность

1. Гость основного справочника.
2. Telegram-бот, через который можно отправлять сообщение.
3. Идентификатор Telegram-чата.
4. Состояние доставки: можно отправлять, заблокирован или недоступен, исключён вручную.
5. Дата последней успешной отправки.
6. Дата и текст последней ошибки.
7. Причина и дата ручного исключения.

Сущность не хранит посещения, сегменты, любимое заведение, факт регистрации в новом боте и согласия нового контура. Эти данные берутся из уже существующих таблиц.

## Этап 1. Модель и администрирование

1. Добавить таблицу исторических Telegram-каналов.
2. Запретить дубли:
   - один исторический канал на одного гостя и одного бота;
   - один Telegram-чат не может принадлежать двум гостям в рамках одного бота.
3. Добавить просмотр в административной панели.

## Этап 2. Первичное наполнение

1. Источник: успешные строки кампании #10.
2. Условие попадания:
   - есть гость;
   - есть Telegram chat_id;
   - доставка реально завершилась успешно.
3. Не переносить строки с ошибками.
4. Повторный запуск команды должен быть безопасным.
5. Если канал уже заблокирован или исключён вручную, команда не должна возвращать его в рабочее состояние.

## Этап 3. Отбор аудитории

1. В рабочем экране гостей использовать новый фильтр: историческая Telegram-аудитория.
2. Фильтр заведений остаётся текущим:
   - был хотя бы один раз;
   - любимое заведение;
   - последнее посещение;
   - все текущие заведения.
3. Если гость зарегистрировался в новом контуре бота, он исключается из исторической аудитории.

## Этап 4. Постановка рассылки

1. Обычная рассылка сначала использует рабочие привязки нового контура.
2. Если их нет, используется проверенный исторический Telegram-канал.
3. Старый запасной маршрут vtelemax остаётся для совместимости, но не является основной базой этой задачи.
4. В задачу отправки записывается идентификатор исторического Telegram-канала.

## Этап 5. Защита перед отправкой

Перед фактической отправкой воркер ещё раз проверяет, не зарегистрировался ли гость в новом боте после создания черновика. Если зарегистрировался, историческая отправка отменяется.

При результате отправки:

1. Успех обновляет дату последней успешной отправки.
2. Ошибка сохраняет дату и текст ошибки.
3. Блокировка переводит исторический канал в состояние “заблокирован или недоступен”.

## Этап 6. Тесты

Обязательные проверки:

1. Команда наполнения создаёт только успешные каналы.
2. Повторный запуск команды не создаёт дубли.
3. Заблокированный или вручную исключённый канал не оживает от повторного импорта.
4. Отбор исторической аудитории не включает гостей нового контура.
5. Черновик рассылки создаёт задачи через исторический Telegram-канал.
6. Воркер отменяет историческую отправку, если гость успел зарегистрироваться в новом боте.
7. Воркер помечает канал заблокированным при ответе blocked/forbidden.

## Что не входит в этот этап

1. Отдельный OLAP-контур для исторических гостей.
2. Дублирование аналитических витрин посещений.
3. Купонные сценарии для исторической аудитории.
4. Полноценный отчёт “вернулся после рассылки”. Его нужно делать отдельным этапом на базе факта отправки и последующих посещений.
